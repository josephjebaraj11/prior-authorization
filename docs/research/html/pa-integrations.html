Integrating Prior Authorization: EHRs, FHIR, and Data Standards

Visual companion to pa-integrations.md — the plumbing that lets a provider's EHR and a payer's system talk without a human retyping data in the middle.

1. Swimlane: a PA request across EHR, clearinghouse, and payer

This is the modern, FHIR-based path a PA request takes today — one lane per organization.

sequenceDiagram participant Clinician participant EHR as EHR (e.g. Epic) participant CH as Clearinghouse
(e.g. Availity) participant Payer Clinician->>EHR: Places order (e.g. MRI) EHR->>EHR: CDS Hooks fires (order-select event) EHR->>Payer: CRD request — "does this need PA?" Payer-->>EHR: Yes + required documentation list EHR->>EHR: DTR session — auto-fills questionnaire from chart Clinician->>EHR: Reviews/completes remaining fields EHR->>CH: PAS submission (FHIR Claim + questionnaire) CH->>Payer: Routed / translated (sometimes to X12 278 internally) Payer->>Payer: Adjudication engine (often a legacy rules engine) Payer-->>CH: Decision: approved / denied / pended CH-->>EHR: Decision returned alt Pended — more info needed EHR->>Payer: CDex — additional documentation Payer-->>EHR: Updated decision end EHR-->>Clinician: PA status shown in workflow
Note: the clearinghouse rarely disappears — most traffic still passes through an intermediary rather than a direct EHR↔payer connection.
